# W96P bridge Implementation Plan

> Execute inline using executing-plans; user requested continuous implementation and no further physical fan tests.

**Goal:** Replicate the official W96P controls through C3 Wi-Fi and prepare Bemfa voice percentage control.
**Architecture:** Arduino firmware, a single BLE worker task and bounded command queue, local HTTP panel, MQTT adapter. Connection and passive reads never apply settings. Secrets entered through local provisioning; cloud optional.
**Tech Stack:** ESP32-C3 Arduino, NimBLE-Arduino 1.4.3, WiFiManager, PubSubClient, ArduinoJson.
**Spec:** ../../../FEATURES.md

## Global Constraints

- Do not operate or flash the physical fan during this implementation.
- No credentials in logs or source; do not reuse the Blinker secret.
- BLE failures and unknown readings must not appear successful or zero.
- All BLE operations run sequentially in one worker, allowing Wi-Fi handling to continue.

## Review Focus

- Bounds checking for all commands, including 128-byte curves and timers.
- Offline commands rejected and queued commands expire; no stale replay on reconnect.
- Turbo/nature/percentage mode transitions serialized and checked.
- Readback confirms state; write acceptance alone is not device confirmation.
- MQTT state uses /up to prevent feedback and does not guess unknown state.
