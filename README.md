# W96P / W96PRO C3 bridge

本项目将 WITRN V3.7 官方网页的蓝牙传输改为通过 ESP32-C3 的本地 HTTP 接口，并提供巴法 MQTT 转接。官方页面副本位于 `tools/w96p-vendor.html`，其内容归原作者所有。原始来源：https://www.witrn.com/witrn/fan/W96P_V3.7.html 。

备份版本：2026-10-30。已撤销误实现的持续亮灯，当前为灯光操作后约 15 秒自动关闭；电机运行/关闭状态实测通过，蓝牙继续保持开启。以“数码屏与蓝灯自动熄灭”章节和 `dist/light-auto-off-test.json` 为准。下方初轮测试中的休眠值、灯光状态及“尚未验证”描述属于历史记录。

本仓库保存源码、生成的本地面板、可直接烧录的 `dist/w96p-c3.factory.bin` 和测试记录；不包含 Wi-Fi 密码、巴法 UID 或设备 NVS。恢复到新的 C3 后需重新配网并填写自己的巴法 UID。下载源码后按文末步骤下载框架缓存再构建；无需构建时可直接使用合并固件。仓库内风扇蓝牙地址为当前设备的地址，更换风扇时须修改 `src/main.cpp` 的 `FAN_MAC`。

## 已实现范围

本地页面保留风速滑条/输入/长按调节、四档及其自定义、五档灯光、硬件定时、Turbo 开关/时长、自然风开关与 128 点曲线、减档方式、蓝牙休眠、显示 SN、序列号/固件版本、电池/电机/USB 电气信息和额定电池能量设置。详见 FEATURES.md。

风扇地址固定为用户确认的设备；不会扫描控制其他设备。开机及重连只连接并读取状态，不写入风速、灯光或休眠设置。BLE 操作串行，过期和跨连接指令丢弃。发送写入后检查回读，回读失败不宣告成功；设备固件若不提供回读，对应控制会显示“未确认”，仍需结合实际状态判断。

## 首次运行

1. 使用 `dist/w96p-c3.factory.bin` 在 **0x0** 烧录；它包含引导程序、分区表及应用。不要把 `.pio/build/c3/firmware.bin` 单独写到 0x0，那个文件只是应用分区。
2. 首次连接 Wi-Fi 通过 `W96P-C3-Setup` 热点配网，热点随机密码从 USB 串口 115200 读取。设备保存热点密码，串口会在启动时显示。路由器须提供 2.4GHz Wi-Fi。
3. 配网页面立即启动，没有 5 分钟等待。连接热点后访问 `http://192.168.4.1/`，在本地面板“设置 Wi-Fi”中填写。已有有效网络时自动连接，从串口输出或路由器客户端列表查看面板地址。
4. C3 自动连接风扇；网页点“连接风扇”加载完整状态。风扇可能只允许一个 BLE 控制端，请先断开手机/原版网页对风扇的连接。
5. 页面通过局域网 HTTP 提供，不应映射到公网。写入使用每次启动随机的防跨站令牌，但没有独立登录鉴权；同一个可信局域网中的设备可访问面板。Wi-Fi 密码和云私钥不通过 API 读取或输出日志；热点配网密码会按上述方式通过 USB 提供。

## 米家

### 数码屏与蓝灯自动熄灭

按用户要求取消持续亮灯和重启恢复亮灯。开灯或调节灯光后，C3 在 15 秒后主动发送 FFFA=0，不区分充电、运行或电机关闭状态；再次操作灯光重新计时。关风扇仍立即关灯，灯可以独立操作，蓝牙保持常开。周期读取状态不会重置熄灯计时，熄灯写入失败时每 2 秒重试。

旧版错误的常亮 NVS 设置会在启动时清除，不再每 3 秒发送正亮度。历史 light-hold 测试仅记录已废弃的常亮实验；当前自动熄灯验证见 dist/light-auto-off-test.json。编译期检查覆盖期限、取消以及 millis 回绕。
### 蓝牙常在线与关机灯光联动

按用户最终要求，C3 上电自动连接风扇，连接后读取 FFF5，必要时设为 0 并回读确认；每 60 秒复查，确认失败时每 10 秒重试该设置。非零休眠设置被明确拒绝，面板自动休眠输入禁用。蓝牙不休眠不代表断电或超出无线范围时仍可通信。

主动点击断开时，本次运行保持主动断开；重新点连接或 C3 再次上电才恢复。风扇端断开或意外丢失连接时，只要用户没有主动断开，C3 沿用原有机制每约 10 秒尝试连接。用户取消了新增的离线云指令补发及复杂重连策略，最终版未保留这些扩展。重新连接要求风扇有电且蓝牙可发现，完全断电或硬关闭蓝牙无法远程唤醒。

关闭风扇（包括本地关机、0% 与云端关闭）分别发送电机关闭和灯光关闭，并分别回读，不通过可选模式读取阻断关机。实体按键/风扇硬件定时导致的实际关机由周期读取检测并联动关灯。自然风临时 0% 不是关机，不据此关灯。

风扇已关闭时，灯仍可以独立打开、调档和关闭；单独关灯不关风扇。连接后读到“风扇关、灯开”也不会擅自把灯关掉。两者只在关机动作时联动。

实机验证记录在 `dist/connection-and-light-test.json`；手动断开保持断开及 C3 全重启后自动连接的验证记录在 `dist/boot-connection-test.json`。测试结束恢复此前“风扇关闭、低档灯光”的状态，并保留 FFF5=0。

### 指定百分比时的启动跳变修复

裸 `on` 等待 650ms，以接收紧随的明确百分比；`on#N` 覆盖待恢复的旧值，80ms 内的百分比变化合并为最新目标。明确百分比后 650ms 内多余的裸 `on` 不覆盖目标；`off` 取消待启动命令。已排队旧风速任务通过版本号丢弃。

风扇的 FFF1 开机指令会进入一档，实测关机时先写 FFF3 再开机仍回到一档。因此开机与目标速度使用相邻写入，优先无响应写，两个写入完成后再统一回读确认，不在两条写入之间等待回读。实测发送时间间隔 0～1ms；这证明减少了控制间隙，不能作为机械转速的亚毫秒测量。

`dist/cloud-speed-fix-test.json` 记录五项真实 BLE 回归测试：旧 1% 后关闭并收到 on+43 仅应用 43、百分比之后补发 on 不覆盖、单独 on 恢复上次21、off 取消待 on、仅百分比也能启动。测试经 USB 注入同一个 MQTT 回调，因此不等同于小爱语音识别及云端顺序测试；真实消息监听另存 `dist/speed-commands.jsonl`。新代码有编译期边界检查，覆盖恢复旧100后明确10、乱序补发、快速更新及 millis 回绕。

测试前处于关闭状态，结束恢复关闭，并恢复此前记忆的10%。

在巴法控制台创建 `w96speed002` 和 `w96light002` 两个 MQTT 主题，在 C3 面板“配置巴法云”中填写 32 位 UID。UID 保存在 C3 的 NVS；不编译进固件。

- 风速：虚拟灯开关对应风扇开关，亮度 1～100 对应风速百分比；开灯恢复上次读取到的非零风速，缺省 10%。
- 实体灯：关灯=关；1～25%=低，26～50%=中低，51～75%=中高，76～100%=高。状态分别回报 25/50/75/100%。
- MQTT 使用 `bemfa.com:9503`，检查 TLS 根证书，等待 NTP 校时成功后连接。客户端 ID 为 UID，用户/密码为空；状态发送到 `<topic>/up`，不会将自己的回报当成控制指令。
- 在米家绑定巴法账号后，再确认设备及百分比语音指令是否可用。目前不承诺任意定时/剩余时间语音查询、曲线或高级参数在米家标准面板中可用。它们在本地控制。

如果开启风扇蓝牙自动休眠，风扇休眠后可能需要物理唤醒；C3 不能在没有可用蓝牙链路时发送唤醒指令。

## 构建与检查

PlatformIO 使用 espressif32 6.9.0 / Arduino 2.0.17、NimBLE 1.4.3，4MB flash，`huge_app.csv`。本地框架缓存由 `tools/fetch_framework.py` 从 PlatformIO 官方镜像获取并比对官方 SHA256；`platformio.ini` 显式引用 `.downloads/framework.tar.gz`，避免重复下载。缓存不应上传版本库。

先准备 PlatformIO 的 Python 环境，再执行：

```text
python tools/fetch_framework.py
python tools/make_panel.py
node --test tools/check_panel.cjs
python -m platformio run
```

`tools/preview.py` 仅在 127.0.0.1:8769 展示页面，所有控制请求均拒绝，绝不连接风扇。`tools/hardware_check.py --controls` 与 `tools/hardware_followup.py` 会实际操作风扇并恢复基线，不属于离线预览。USB 入口使用 `@` 开头的 JSON 行并调用同一个 BLE 队列；接收缓冲 2048 字节。`.pio/build/c3/firmware.bin` 和最终合并镜像须保持同一次构建；最终刷机包通过 esptool merge_bin 生成。当前分区不提供 OTA 更新入口。
